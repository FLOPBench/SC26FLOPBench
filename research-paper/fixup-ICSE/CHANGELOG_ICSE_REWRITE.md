# ICSE Rewrite Changelog

## Major manuscript changes

- Repositioned the paper from an HPC-style profiling study to an ICSE paper about execution-free performance reasoning for AI-assisted GPU software engineering.
- Rewrote the introduction around the software-engineering problem: scarce profiler access in LLM-assisted optimization loops.
- Split the evaluation into distinct tasks: zero/nonzero detection, nonzero `RAI` regression, nonzero bandwidth-vs-compute triage, and practical cost/latency analysis.
- Added an aggregate shared-subset results table to replace the old figure-heavy presentation.
- Added a fixed-budget profiling-queue analysis that ranks rows by predicted `RAI` relative to the balance point and reports compute-bound recall at a 10% profiling budget.
- Added deterministic source-lexical and SASS-mnemonic reference heuristics, a grouped runtime`x`GPU context-median baseline, and lightweight grouped random-forest/extra-trees baselines over source and source+SASS features.
- Extended the utility analysis with a 5/10/20/30% budget sweep against the strongest static baselines.
- Added an appendix shared-subset class-balance table, nonzero compute-bound precision/recall/F1 summaries for all six LLM configurations, and raw Task A/C/D confusion-count exports for both the LLM rows and the static references.
- Added five-seed sensitivity summaries for the learned baselines so the comparison is not tied to a single seed.
- Added paired source-vs-SASS significance checks and paired bootstrap confidence intervals from the released artifact.
- Documented the committed model identifiers and released decode defaults used by the direct-prompting pipeline.
- Replaced the old main-text failure-analysis RQ with a stronger regime-by-regime best-LLM-versus-best-static comparison, promoted that comparison table into the main results section, added a compact deployment-routing matrix in the discussion, moved the feature heatmap to the appendix, added two illustrative released-row case studies, and added a BH-corrected feature-prevalence sanity check recovered from the restored PostgreSQL dumps.
- Tightened the claim language throughout: triage signal rather than profiler replacement, execution-free at prediction time rather than broadly hardware-free.
- Reframed the feature analysis as exploratory because the released feature labels are generated by an auxiliary LLM-voting pipeline.
- Added a dedicated threats-to-validity section with explicit scope, coverage, reproducibility, and baseline limitations.
- Cleaned the cited IEEE proceeding entries so the bibliography compiles without the earlier HeCBench `n.d.` artifact or cited-entry metadata warnings.

## Artifact and reproducibility changes

- Moved to a current ACM `acmart` project scaffold in anonymous review mode.
- Corrected the conference-layout activation bug by restoring `\maketitle`, which is required for `acmart` to enter the `sigconf` two-column topmatter/body path.
- Preserved key figures from the original artifact while pruning the main text to the figures that directly support the ICSE argument.
- Added `analysis/generate_additional_artifacts.py` to regenerate the static-baseline tables, class-balance and compute-bound-PRF tables, budget-sweep tables, learned-baseline seed-sensitivity tables, paired source-vs-SASS summaries, and raw confusion-count CSVs from local artifacts.
- Added `analysis/generate_feature_vote_artifacts.py` to regenerate the appendix feature-prevalence and adjusted-`p` summaries from restored `gpuflops_db` and `code_features_db` instances.
- Documented the current public benchmark mirrors in `README.md` while keeping the manuscript anonymous.
