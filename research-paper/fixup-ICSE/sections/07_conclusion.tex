\section{Conclusion \& Future Work}
\label{sec:conclusion}

We framed early GPU performance reasoning as a software-engineering problem: deciding a kernel's \bandwidthbound/\computebound Roofline regime from software artifacts alone, before any profiling run, for developers and coding agents that cannot reach the target accelerator.
Evaluating three LLMs on 254 HeCBench kernels across four NVIDIA GPUs, we find that prompting already solves this task for the FP32 and FP64 regimes from source alone, while FP16 sits at chance until cross-compiled SASS is supplied, after which the stronger models classify it near-perfectly.
We demonstrate that FP16, the hardest regime, is governed by the evidence tier rather than the model: the cross-compiled SASS that closes the gap needs no target hardware.

This regime prediction is also practical to deploy: it is cheap and tiered (a budget model triages FP32 for a fraction of a cent per query with no GPU), stable enough under repeated queries to act on, and beats lightweight static baselines in the high-value regimes.
Because no single model-and-evidence pairing wins across every precision, deployment should be a cost-tiered cascade routing each precision to the model and evidence tier that handle it best, not an LLM-only oracle.

Several directions remain open.
The cost-tiered cascade is so far a routing guide, not a system validated end-to-end; building and measuring it inside a real agentic optimization loop is the natural next step.
Finally, complementary studies include a memorization analysis to probe generalizability across kernel source perturbations, and broader coverage of hardware and runtimes (AMD/Intel GPUs, HIP/SYCL), along with end-to-end warm-cache kernel behavior.
